## Proposed design contract (requires approval, not implementation)

1. **One authorized discovery read boundary.** Typed query in, safe combined page out: results, total, authorized existence, canonical state and refresh metadata. Authorization/domain package owns predicates and facet projection. The handler owns HTTP parsing/serialization only. SQL matching/rank/count/page share the same authorized candidate relation and coherent database view. Do not fetch all ten catalogs into Go or introduce an external search service.
2. **Per-type explicit searchable values.** Return match category/relationship metadata only when authorized. One result identity may have many permitted matching fields; score by its best allowed match. Never redact after ranking. Item SKU belongs to Pricebook, Cost to Cost; Lease financial values remain Billing-gated.
3. **List state is presentation, not authorization.** Store only bounded versioned filter/sort/page-size configuration scoped by company/user/list. Keep transient history page/scroll in browser navigation state, not result bodies. Resolve explicit URL, then saved configuration, then default; always revalidate under current authority. Do not silently run a broader query when a requested sensitive filter becomes unavailable.
4. **Preserve domain-owned Lease semantics.** Extract/reuse a narrow read helper only where needed; do not couple discovery to report export, billing generation or activity-feed authorization. A global search route is not an API entitlement.
5. **Failure contract.** Selected authorized sources and required projection data succeed together or return a safe unavailable response. A stale list, if retained, is marked as belonging to the prior query; authority uncertainty requires hiding it until revalidation. Keep Retry and current filter inputs. Do not expose SQL/driver errors.
